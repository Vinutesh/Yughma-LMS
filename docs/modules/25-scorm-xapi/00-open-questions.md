# Open Questions — SCORM / xAPI

Per [MODULES.md](../../MODULES.md) §29, this is "mostly backend/runtime; thin UI surface" — the real complexity is server-side (package extraction, LRS statement storage), which doesn't exist yet. This pass builds the complete UI shell and the one piece of frontend logic that's genuinely security-relevant regardless of backend status.

- **SCORM upload adds a new Lesson content type** (`scorm`), alongside the existing video/text/file/link types from [Lessons](../08-lessons/) — a SCORM package is content, authored the same way any other lesson content is attached.
- **The SCORM player MUST render inside a sandboxed iframe, on message-passing terms, never trusted directly.** This isn't a nice-to-have — SCORM packages are learner- or instructor-uploaded zip files full of HTML/CSS/JS that executes in the browser. See [SECURITY_REVIEW.md](../../SECURITY_REVIEW.md): uploaded HTML/JS is code, not content. The player wireframe below and its implementation both reflect this: `<iframe sandbox="allow-scripts allow-same-origin">` at most, served conceptually from an isolated path, with SCORM API calls (`LMSInitialize`, `LMSSetValue`, etc.) proxied through `postMessage` rather than direct DOM access into the parent frame. Real package extraction/validation (zip-slip protection, manifest validation) is backend work and out of scope here — this module's job is to make sure the frontend never assumes uploaded content is safe to render un-sandboxed.
- **xAPI statement viewer is read-only, admin/debug-only** — a list of (mock) statements (`actor`, `verb`, `object`, `timestamp`), not an authoring surface. Real xAPI requires a real LRS (Learning Record Store) backend; this pass mocks statements generated from existing lesson-completion events so the screen has real shape to react to later.
- **LRS connection settings is a stored config form** (endpoint URL, auth key) — saved but not connected to anything real, same "record the config, no live integration" pattern as Trial & Plan's plan selection.
- **No SCORM 1.2 vs 2004 version-negotiation UI** — out of scope; that's a backend/runtime concern once real packages are actually parsed.
