# Step 1 — User Journey — Notifications

## Journey 1 — Catching up on everything

1. From the bell panel (Shell), "See all" opens the full Notification Center — same list, further back in time, filterable by category and read/unread.
2. Clicking any entry navigates to its source (a graded submission, a new course, etc.) exactly like the panel does — same click-through behavior, just more history available.

## Journey 2 — Tuning what they hear about

1. Personal Settings → Notifications.
2. Sees the category groups, each with independent in-app/email toggles — e.g., turns off email for "Course Updates" but keeps in-app on, because they don't want inbox noise but still want the badge count.
3. Some categories are not fully disable-able (e.g., security-relevant notices like a password change) — shown as always-on, not offered as a toggle, so nobody accidentally opts out of something that matters for their own account safety.

## Edge cases

- **All notifications turned off for a category:** the bell simply never gets an unread badge for that category again — no confirmation needed, it's fully reversible.

## What this rules in for Step 2 (User Flow)

- Notification Center reuses the panel's click-through behavior — not a new interaction pattern.
- A small subset of notification categories are non-optional and rendered without a toggle at all.
